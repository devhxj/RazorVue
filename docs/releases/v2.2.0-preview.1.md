## Razor adapter migration

Use the same 2.2 preview version of the Jazor SDK and RazorVue packages.

- `Jazor.Vue` supplies `VueRouterLink`, `VueRouterView`, and the three Blazor native event and payload extension classes. Their C# namespaces and source signatures are preserved. Rebuild assemblies using these types after upgrading their references.
- `Jazor.Vue` ships `ECMAScript.VueContract.dll` with the original assembly name, version, and public types. `ECMAScript.Vue` 2.2 no longer carries this DLL. Keep the shared Vue and Router packages aligned with the version mapped by `Jazor.Vue` to avoid duplicate type definitions from older packages.
- `ECMAScript.Vue` and `ECMAScript.VueRoute` continue to provide the shared Vue and router APIs. Projects using these APIs alone can keep their shared-package references.

Existing Razor projects should update their direct `Jazor` and `Jazor.Vue` references together. Projects using the moved types outside a Razor project can reference `Jazor.Vue` for those types. Clean and rebuild modified projects and their dependent libraries.
