# RazorVue

RazorVue compiles .NET Razor components to Vue render-function modules. It binds the final C# generated by the official Razor Source Generator and delegates C# lowering to Jazor. Existing RazorVue applications can keep their .razor files, component contracts and ModuleCatalog output.

This repository maintains the Razor SDK integration, Vue runtime bridges, Jazor.Admin, and the following strongly typed Razor component bindings.

| NuGet package | Authoring surface |
| --- | --- |
| [ECMAScript.Vuetify](src/ECMAScript.Vuetify) | Vuetify components, props, events and slots |
| [ECMAScript.TDesign](src/ECMAScript.TDesign) | TDesign Vue Next components |
| [ECMAScript.ElementPlus](src/ECMAScript.ElementPlus) | Element Plus components and services |
| [ECMAScript.VueDataUi](src/ECMAScript.VueDataUi) | Vue Data UI charts and datasets |
| [ECMAScript.Lucide](src/ECMAScript.Lucide) | Tree-shakeable Lucide Vue icons |
| [ECMAScript.FilePond](src/ECMAScript.FilePond) | FilePond upload component and imperative API |
| [ECMAScript.VueDraggable](src/ECMAScript.VueDraggable) | Drag-sort component and composable |
| [ECMAScript.WangEditor](src/ECMAScript.WangEditor) | Rich-text editor, toolbar, and configuration |

A Razor authoring project references both Jazor and Jazor.Vue directly. Use the shared SDK version in the same row as your RazorVue packages. The binding packages keep their NuGet IDs and C# namespaces across repository moves.

The FilePond, VueDraggable, and WangEditor source is maintained here. The next standalone release is prepared against the shared SDK at 2.1.0-preview.6. [Preview 8 notes](docs/releases/v2.1.0-preview.8.md)

The 2.2 migration moves the Razor Router components, Blazor event extensions, and Vue injection contracts into the `Jazor.Vue` package. Upgrade the shared packages and `Jazor.Vue` together and rebuild the projects that use the moved types. [2.2 migration notes](docs/releases/v2.2.0-preview.1.md)

```xml
<ItemGroup>
  <PackageReference Include="Jazor" Version="2.1.0-preview.6" />
  <PackageReference Include="Jazor.Vue" Version="2.1.0-preview.7" PrivateAssets="all" />
</ItemGroup>
```

## Build and release

Use the .NET SDK selected by global.json. This repository builds against the Jazor version in Directory.Build.props and consumes its NuGet assets. Once that SDK is available on NuGet, run the following from a clean checkout:

```sh
dotnet build RazorVue.slnx
dotnet run --file scripts/csharp/verify-razorvue-coverage.cs
dotnet run --file scripts/csharp/pack-release.cs
dotnet run --file samples/RazorVue.Authoring/verify-smoke.cs -- --configuration Release --package-output artifacts/packages
dotnet run --file scripts/csharp/verify-windows-ssr-release.cs -- --package-source artifacts/packages --path-base /todo
```

The two browser checks use Chrome on Windows. Packing also builds a standalone Razor project with the component bindings, Router proxies, native events, and Vue injection contracts. To verify an unpublished shared SDK, put the Jazor, ECMAScript.Vue, ECMAScript.VueRoute, and ECMAScript.Style candidate packages into one local feed and pass that directory as the second argument to `pack-release.cs`. Pass the same directory as `RestoreAdditionalProjectSources` when building the solution.

A v-prefixed Git tag sets the version of Jazor.Vue, Jazor.Admin, and all eight bindings. The publish workflow runs verification before NuGet Trusted Publishing. NuGet.org must authorize the repository, the `nuget-publish-ref.yml` workflow, and the production environment for every package ID.

The Razor compiler source history was extracted from [Jazor at preview 5](https://github.com/devhxj/Jazor/tree/v2.1.0-preview.5). The bindings carry their original source history.
